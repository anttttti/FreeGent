What is FreeGent

FreeGent is an AI agent system with a browser WebUI, terminal TUI, and headless CLI. It routes requests through a priority list of models, automatically retrying on rate limits and falling back to the next available provider.

The core design trades per-model context depth for parallel throughput. A Director agent breaks tasks into subtasks that run as independent workers, each on their own context window — effective on 7B–70B models with 4k–32k context budgets.

WebUI
Browser chat interface. Persistent workspace, file editor, skills panel, and model settings.
TUI
Interactive terminal session. Same agent core, no browser required. Works over SSH.
CLI
Headless, non-interactive. For scripting, benchmarks, and CI pipelines.

Installation

Requires Node.js 22 or later.

shell
$ git clone https://github.com/anttttti/FreeGent
$ cd FreeGent
$ npm install

# Set up credentials (outside the repo, safe from accidental commits):
$ mkdir -p ~/.config/freegent
$ cp .env.example ~/.config/freegent/credentials
# edit ~/.config/freegent/credentials and add at least one API key

Put your API keys in ~/.config/freegent/credentials — see Configuration. The dev server loads the file automatically.

WebUI

The browser interface is served by a Vite dev server. It includes a chat panel, a file workspace, a model priority list, a skills manager, and per-session settings.

Launch

shell
$ npm run dev
# → http://localhost:5000

# Custom port:
$ FG_PORT=8080 npm run dev

# Expose on local network:
$ FG_PORT=5000 FG_BIND=0.0.0.0 npm run dev

API keys

Open Settings → Models → API Credentials and paste your key, or put your keys in ~/.config/freegent/credentials — they are forwarded to the browser automatically and never stored server-side.

Model priority

Go to Settings → Model → Model Priority to arrange which models are tried first. FreeGent picks the first non-rate-limited entry and waits for the shortest cooldown when all are cooling down.

Local LLM endpoint

Go to Settings → Model → Custom Endpoint and enter your vLLM, Ollama, or LM Studio base URL (e.g. http://localhost:8000/v1).

TUI (Terminal UI)

An interactive terminal session built with Ink. Runs the same agent core as the WebUI. Useful for remote servers, SSH sessions, or workflows where a browser is inconvenient.

Launch

shell
# Auto-detect from ~/.config/freegent/credentials or env vars:
$ npm run tui

# Explicit credentials:
$ npm run tui -- --provider google --api-key AIza...
$ npm run tui -- --provider mistral --model mistral-medium-3.5 --api-key ...

# Against a local model:
$ npm run tui -- --api-url http://localhost:8000/v1 --provider custom --model qwen3

The TUI auto-detects the provider from standard environment variable names (GEMINI_API_KEY, OPENAI_API_KEY, etc.) and from ~/.config/freegent/credentials (loaded automatically).

CLI (Headless)

Non-interactive agent runs for scripting, benchmarks, and CI pipelines. The CLI uses the same agent and tool implementations as the WebUI.

Examples

shell
# Run a task with file tools:
$ npx tsx fg-run.ts --task "Refactor auth.ts to use async/await" \
  --workspace ./myproject \
  --provider google --api-key $GEMINI_API_KEY

# Read task from a file:
$ npx tsx fg-run.ts --task-file task.txt --workspace ./myproject

# One-shot LLM call, no tools:
$ npx tsx fg-run.ts --prompt "Summarise: $(cat notes.txt)" --provider google

# Combined provider+model selector:
$ npx tsx fg-run.ts --task "Write unit tests" --llm "google|gemini-3.6-flash"

# Local model:
$ npx tsx fg-run.ts --task "Write unit tests for src/api.py" \
  --api-url http://localhost:8000/v1 --provider custom --model qwen3

Configuration

API keys

Recommended: put your keys in ~/.config/freegent/credentials — it lives outside every git repo, so it can never be accidentally committed. The dev server, TUI, and CLI all load it automatically. Keys are forwarded to localStorage in the browser and sent directly to each provider — never stored by FreeGent's server.

~/.config/freegent/credentials
GEMINI_API_KEY=AIza...
OPENROUTER_API_KEY=sk-or-...
MISTRAL_API_KEY=...
GROQ_API_KEY=gsk_...
CEREBRAS_API_KEY=csk-...
NVIDIA_API_KEY=nvapi-...
OPENAI_API_KEY=sk-...

# Optional — web search tools
BRAVE_API_KEY=...
TAVILY_API_KEY=...

Local LLMs — vLLM

Serve any HuggingFace model locally. FreeGent works well with Qwen3, Gemma 4, Devstral, and similar tool-calling models.

shell — vLLM (Qwen3 27B example)
$ vllm serve cyankiwi/Qwen3.6-27B-AWQ-INT4 \
  --port 8000 \
  --max-model-len 20000 \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3_coder \
  --reasoning-parser qwen3
# Endpoint: http://localhost:8000/v1

Local LLMs — Ollama

shell
$ ollama run qwen2.5-coder:7b
# Endpoint: http://localhost:11434/v1

In the WebUI, enter the endpoint at Settings → Model → Custom Endpoint. For CLI/TUI, pass --api-url http://localhost:<port>/v1.

Skills

Skills are Markdown files in skills/<name>/SKILL.md that inject guidance into the agent's system prompt when a trigger fires. They let you customise agent behaviour for your project without touching source code.

Enable skills in Settings → Skills, or drop a SKILL.md into the workspace skills/ directory. Skills fire based on:

keyword in message file extension in workspace tool call result repeated tool use session start task start media attachment type N consecutive failures
